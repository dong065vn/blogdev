# /brain - Brainstorm & Requirements

## Cách dùng
```
/brain [ý tưởng/vấn đề]
```

## Quy trình

### Step 1: Understand - Hiểu vấn đề
1. Lắng nghe user mô tả ý tưởng/vấn đề
2. Đặt **5 câu hỏi quan trọng nhất:**
   - Target users là ai?
   - Core problem đang giải quyết là gì?
   - Đã có solution tương tự chưa?
   - Constraints (thời gian, budget, tech stack)?
   - Success metrics là gì?

### Step 2: Explore - Khám phá giải pháp
3. Đề xuất **2-3 approaches khác nhau** (không chỉ 1)
4. So sánh Pros/Cons mỗi approach:
   - Complexity vs Value
   - Time to implement
   - Scalability
5. Brainstorm alternatives và edge cases

### Step 3: Prioritize - Ưu tiên hóa
6. Liệt kê features theo **MoSCoW method:**
   - **Must have** - Không thể thiếu
   - **Should have** - Quan trọng nhưng không critical
   - **Could have** - Nice to have
   - **Won't have** - Loại bỏ (lần này)

### Step 4: Confirm - Xác nhận
7. Tóm tắt requirements cho user review
8. Xác nhận trước khi chuyển sang thiết kế

## Skills sử dụng

## Output
- Danh sách requirements đã confirmed
- Feature list theo mức ưu tiên (MoSCoW)
- Tech stack recommendation
- Next steps rõ ràng
